Part 2: Run-length Encoding

Nice job! You might have seen in the last page that JPEG is a lossy compression format. But what does being lossless really mean? How can you make an image smaller without losing any details?

Well, a lot of data storage is actually really inefficient. Imagine an image that stores three values -- red, green, and blue -- for each pixel.

That's three numbers for each pixel. Doesn't seem like much for this 5x5 image, but recall that an HD screen is 1280x720 pixels: nearly three million numbers for each image!

Run-length encoding reduces file size by taking advantage of repetition in image encodings. For example, in the image above, you can see that the pixels are either yellow or black and that the yellow pixels often appear in sequences of more than one.

That means that we can instead describe the image as having five yellow pixels rather than repeating "yellow" five times.

See how much less data we need to encode the same image?
